Case file · October 2026

The week the internet's elephant caught fire

How an AI-discovered bug in PHP, a language behind about 70% of websites, leaked early and pushed governments across Europe and beyond to take their own websites offline. Written in plain language, with the full timeline, the people involved, and the conspiracy theories, each checked against the evidence.

CVE-2026-109618 CVE-2026-109619 CVSS 9.2 · Critical Patched 21 Oct 2026
The 30-second version
  1. PHP is the software engine that runs most websites (WordPress, Wikipedia, many government portals).
  2. In August 2026, security researchers using AI models found two serious bugs in PHP. Some of this code dates back to 2012. The bugs let a stranger take control of a server without logging in.
  3. The plan was to fix it quietly and announce on 22 Oct. But details leaked on 20 Oct, and someone was already testing an attack on 17 Oct.
  4. Patches went out early on 21 Oct. Governments in Finland, the Netherlands, the UK, France, Germany, Belgium, Czechia, Canada and others took their own sites offline as a precaution while they patched.
  5. So the sites mostly went dark because developers took them down to protect them, not because hackers destroyed them. Attackers really did start scanning within hours, though.

01 · The basics

What actually is "PHP2Shell"?

The name combines PHP, the programming language, with shell, hacker slang for a command line on someone else's computer. Put together, it means "a way to go from PHP to full control of the server."

~70%of websites with a known server language run on PHP (W3Techs)
2012 → 2026Every PHP version from 5.4 to 8.5 had at least one of the bugs
0passwords needed. The attack works without logging in
2.6M – 37Minternet-facing PHP systems exposed, depending on who counted (VulnCheck, Bitsight)
79%of PHP services found by Modat were on old, unsupported versions
13staff at the PHP Foundation, which runs on donations (The Guardian, via Wikipedia)

Why it was frightening: the bugs are in PHP itself, not in a particular website. A simple "Hello World" page on an affected PHP version could be vulnerable. The researchers showed full takeovers of WordPress, Drupal and Joomla, which together power a huge share of the web. Wiz compared it to Heartbleed (2014), and many people compared it to Log4Shell (2021).

02 · Explain it like a restaurant

How the two bugs work

Think of a website as a restaurant. PHP is the kitchen. Every visitor's request is an order that the kitchen cooks into a web page.

Bug 1 · CVE-2026-109618

The overloaded kitchen ("out-of-memory corruption")

An attacker sends one huge, oddly shaped order. The kitchen runs out of counter space (memory). It should calmly say "sorry, too big," but in the rush the chef scribbles over the recipe book. The attacker has planned the scribble so it reads as their own instructions, and the kitchen follows them. That means the attacker's code runs on the server.

Technical clue that defenders watch for: oversized or malformed PHPSESSID cookies and big multipart uploads, followed by "memory limit" errors or HTTP 500s. Security firm Hadrian said most real-world attacks abused PHP's session upload-progress feature.

Bug 2 · CVE-2026-109619

The table nobody wiped ("stale global state" / use-after-free)

After each customer leaves, the waiter is meant to clear the table. Sometimes PHP forgets to wipe a few notes. The next customer, who may be an attacker, can read what the last person left behind: passwords, login tokens, API keys, certificates. In some cases the attacker can also leave a note the kitchen later obeys, which gives them control.

"Use-after-free" means the program keeps using a piece of memory after it has handed that memory back, a bit like writing on a whiteboard someone else is already using.

The attack, step by step

This is also why the UK's NCSC told organisations to check for backdoors even after patching. Patching locks the door, but it doesn't remove anyone who already got inside.

03 · What happened when

The timeline

From a 14-year-old bug to governments pulling the plug in about 72 hours.

2012

PHP 5.4 is released

The earliest version found to be affected. The flawed code sits unnoticed for years.

2024

A warning that went nowhere

A PHP core developer found the out-of-memory problem behind one flaw during an audit. The team couldn't agree on a fix, and nobody believed it could really be exploited, so it was set aside.

1–11 Aug 2026

AI finds the bug

Ryan Austin at Calif, an AI red-team firm working under OpenAI's "Patch the Planet" programme, finds it with GPT-5.6 Sol. OpenAI reports the same root cause separately. Sources give different dates: 1 Aug, 11 Aug, or "July."

19 Aug 2026 →

Wiz joins in

Wiz Research (owned by Google) finds more variants using Gemini, GPT-5.6 and its own tool. Wiz names it "PHP2Shell." Over the next weeks the PHP team works on fixes in private (this is called an embargo).

16–17 Oct 2026

Chainguard finds it too

Chainguard hears that a disclosure is coming and finds the same flaw that night with its own AI system. It joins the private coordination group on 17 Oct.

17 Oct 2026

The first mystery probe

Amazon's honeypot network (MadPot) records an attempt to exploit the bug, four days before anyone was told. It came from an anonymising service in Australia. Amazon: "it remains unclear how the actor acquired exploit information."

20 Oct 2026 · 15:20 UTC

The leak

A Hacker News user, "petecooper", posts a "Tell HN" warning citing a "reliable source": two PHP RCE bugs, the CVE numbers, a (wrong) score of 10.0, and a release date of 22 Oct. watchTowr confirms the details on X. In the rush, Calif accidentally publishes a demo video of the exploit, which is deleted but copied. PHP brings the release forward to 21 Oct.

21 Oct · 03:02 UTC

Cloudflare starts blocking

Emergency firewall rules go up. Cloudflare's CTO calls them a "STOPGAP only."

21 Oct · 07:41 UTC

Chainguard ships early

About six hours before the official release, Chainguard publishes fixed builds, citing overnight attacks while European maintainers slept. Attackers can now compare old and new code to see exactly what changed. ELLIO's sensors see their first PHP2Shell request less than an hour later.

21 Oct · 13:34 UTC

Official patch

PHP 8.5.12, 8.4.27, 8.3.36 and 8.2.35 are released. Source patches follow for end-of-life 7.4, 8.0 and 8.1. Sansec predicts "mass attacks within 15 minutes."

21 Oct · evening

The lights go out

Finland, the Netherlands, France, Germany, Belgium, Czechia, the UK, Canada and others take sites offline to patch. The NSA advises going offline if you can't update. Wikipedia's operator, 4chan, Something Awful, the Internet Archive and several Japanese games go down too.

22–24 Oct 2026

Aftermath

Cloudflare's CEO says attempts grew from "thousands" to "millions." A suspected North Korea-linked scanning campaign is reported. Fake exploit code and prank malware appear on GitHub. The leaker apologises publicly.

06 · The bad guys

So who were the "hackers"?

An important point: nobody "hacked the governments" to cause the shutdown. The people who found the bug were the good guys. The hackers are the ones who rushed to use it after it leaked.

The 17 October ghost

A single probe of Amazon's honeypot, four days early, from an anonymising network in Australia. Nobody knows who it was or how they knew. Amazon said there was "no evidence" it was harmless.

The swarm after the leak

Multiple groups sent different payloads, a sign of several separate actors. Scanners even labelled themselves (php2shell-scan/109618, p2s-rider). Pantheon blocked 60,000+ suspicious requests in a day.

Suspected North Korea (Lazarus)

CYFIRMA reported a slow, deliberately "low-volume" campaign from 21 hijacked servers. It shortlisted 216 unpatched targets, mainly governments, banks, airports and payment platforms in the US, Japan, Korea, India, the UAE, the EU and elsewhere. They point to North Korean vocabulary in a private chat channel. Confidence: moderate.

Pranksters and scammers

Fake "proof-of-concept" exploits were posted on GitHub. JFrog found one that just changed the victim's wallpaper to NSFW images. Lesson: never run random exploit code you download.

Did any government actually get breached through PHP2Shell? As of the latest reporting, no confirmed case. Palo Alto's Unit 42 linked one European government agency attack to PHP2Shell, then withdrew that claim: "We are unable to confirm that initial access is associated with the specific PHP2Shell CVEs."

07 · Conspiracy corner 🕵️

The theories, and what the evidence says

These ideas circulated on Hacker News, X and tech blogs. Each one gets a verdict based on what's actually been reported.

Unsolved mystery

"Someone knew before everyone else"

The 17 Oct probe came before the leak and before Chainguard's early release. That means someone had working knowledge of the bug while it was still secret. The private coordination group was big (several companies plus the PHP team), and Hacker News commenters noted that every extra person briefed is another possible leak.

Evidence: real and unexplained. Amazon itself says it's unclear how they knew. Another possibility: AI makes it easier for more people to find the same bug independently.

No evidence

"AI companies leaked it on purpose for hype"

Some HN commenters felt the slick branding (a name, a website, elephant mascots, model credits) looked like marketing for AI models. One said it was "marketed as if it were the first RCE found in human history." OpenAI called it one of the most significant vulnerabilities its models had found.

Evidence: the known leaker is an individual developer who apologised. No reporting shows an AI company planted the leak. The "it felt like an ad" criticism is opinion, though a common one.

Disputed

"Chainguard broke the embargo to help its paying customers"

The PHP Foundation said publishing early let attackers study the fix while everyone else waited.

Evidence: Chainguard admits it shipped early but says the builds were public, not customer-only, and that it acted because attacks were already happening overnight while the maintainers slept. The early release is confirmed. Why they did it is disputed.

Partly true

"The Calif video leak was a PR stunt"

Some suspected the accidentally public exploit video was a publicity move gone wrong.

Evidence: the video really was published and then deleted, and copies spread. Every source calls it a mistake. Nothing shows it was intentional.

Mostly true

"They knew about this bug in 2024 and ignored it"

An audit in 2024 found the out-of-memory problem. It went unfixed because the team couldn't agree on a fix and it seemed impossible to exploit.

Evidence: confirmed. But "ignored" is unfair: a tiny volunteer-heavy team judged it low priority. The real issue critics raise is funding. The Guardian contrasted the PHP Foundation's 13 staff with the billions invested in AI.

Moderate confidence

"North Korea is behind it all"

Headlines about Lazarus made some people think North Korea caused the incident.

Evidence: North Korean-linked actors are suspected of exploiting the bug after it leaked (CYFIRMA, moderate confidence). They didn't create it or cause the leak. Plenty of others were scanning too.

Overblown

"A third of the internet is now permanently hackable"

Viral posts on X said old, unsupported PHP versions would never get a fix.

Evidence: maintainer Ondřej Surý pushed back. Source patches exist for 7.4, 8.0 and 8.1, and he built installable packages for old versions. The real risk is people who never update, not that a fix is impossible.

Retracted

"A European government was hacked with PHP2Shell"

Unit 42 linked an attack on a European government agency to the bug.

Evidence: Unit 42 later retracted the link. No confirmed government breach so far.

The bar under each theory is my rough sense of how well the evidence supports it.

Forum and community chatter

The main discussion happened on Hacker News, where the leak itself appeared, and on X. I couldn't find indexed Reddit threads or YouTube explainers in search. The closest to a video breakdown is Huntress researcher John Hammond's rapid-response write-up. Here are the main themes, paraphrased:

Hacker News commenter, paraphrased

Long memory-safety debate on HN, paraphrased

Reactions to petecooper's apology

HN humour
AI-driven co-discovery makes it more likely that several people find the same bug, so maybe long embargoes no longer reduce risk.
Art Manion, FIRST (via TechTarget)

The bigger lesson everyone is talking about

Amazon's CISO CJ Moses summed it up: AI is making it cheaper to turn a patch into a working attack, so "more actors can act within hours or even minutes." PHP2Shell may be the first big example of the AI-vs-AI race: AI finds the bug, and AI helps attackers weaponise the fix. Tolmo said it built a working exploit in under a day.

09 · Not the same story, but related

The India angle (in case this is what you heard about)

Separate incident

Telangana's TG-iPASS portal hit by ransomware

On 22 Oct 2026 at about 11:36 pm, the day after the PHP2Shell patch, Telangana's single-window portal for industrial approvals went down. Officials found the database encrypted, with files renamed to .vgb, and a ransom note that asked for no money, just giving an email address. The Telangana Cyber Security Bureau (TGCSB) registered a case under IT Act Sections 43 and 66. Backups exist and restoration is underway.

No reporting links this to PHP2Shell, and whether data was stolen is still being investigated.

Separate incident

SBI customer data alert

On 16 Oct 2026, CERT-In alerted State Bank of India about suspected exposure of customer data on the dark web. I found nothing connecting this to PHP2Shell or TG-iPASS.

India was also on CYFIRMA's list of countries with targeted unpatched hosts in the suspected Lazarus scan.

10 · Jargon buster

Glossary

PHP
A programming language that builds web pages on the server. Its mascot is a blue elephant (the "elePHPant").
RCE
Remote Code Execution: making someone else's computer run your commands over the internet. This is about as bad as a bug gets.
Shell
A command line. "Getting a shell" means getting control.
CVE
An official ID number for a known security bug, e.g. CVE-2026-109618.
CVSS
A severity score out of 10. A 9.2 is "critical."
Zero-day
A bug attackers can use before a fix exists.
Embargo
A private period when finders and fixers keep a bug secret until the patch is ready.
Proof of concept (PoC)
A demo showing that an attack really works.
Honeypot
A fake server set up to attract and record attackers, like Amazon's MadPot.
WAF
Web Application Firewall: a filter (e.g. Cloudflare) that blocks bad requests before they reach a site.
Backdoor
A hidden way back in that an attacker leaves behind.
Lazarus Group
A hacking group widely linked to North Korea.
